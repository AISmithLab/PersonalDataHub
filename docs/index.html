An AI assistant that lives on your phone, not in someone else's cloud.

PersonalDataHub reads your SMS, photos, calendar, email, and GitHub — only the sources you connect, only the data you allow — and answers from a chat UI running on the phone itself.

What it actually is

The app is a React Native shell around an embedded server — the same backend used by the self-hosted desktop version — running inside the phone in a background Node.js thread, talking to the on-screen chat UI over 127.0.0.1. There's no PersonalDataHub account, no server you sign up for, and no telemetry sent back to us.

Data still leaves the phone in two cases you control: each connected service's own API (e.g. Gmail's, when you ask about email), and the AI model itself — you bring your own API key for OpenAI, Anthropic, Gemini, or Groq, and whatever the assistant reads to answer your question is sent to that provider as part of the request.

What
Standing rules triggered by an event (text arrives, photo saved, email comes in, calendar event starts), each scoped to specific sources

Photos are stripped of EXIF metadata (GPS coordinates, device serial, etc.) by default before the assistant ever sees them — you can turn that off per-source if you want it.

How access is actually controlled

Zero access by default

Connecting a source does not automatically expose it — you set filters on top (date ranges, senders, keywords, hidden fields) before the assistant can query it.

Email is staged

Drafting, replying, or sending a Gmail message sits in a staging queue until you approve it — there's no code path for the assistant to send email directly.

SMS auto-reply is the exception

It's an opt-in toggle: when on, replies send immediately with no per-message approval, so you can be answered while you're away from the phone. Turn it off and the assistant can only read, not send.

No deletion

There's no delete endpoint for any connected source. The assistant can read and propose, nothing more.

Everything is logged

Every read and every proposed action is written to a local audit log with a timestamp and a purpose string.

Encrypted at rest

Tokens are encrypted (AES-256-GCM), and on the desktop version the server only binds to 127.0.0.1.

None of this stops you, once you approve something, or stops a connected service's own quota/rate limits — see the full threat model for what it doesn't cover.

Current status

This is an early-stage, actively-developed open-source project — not a polished product.

Ready

Android

Builds via nightly CI. SMS, Photos, Calendar, Gmail, and GitHub are all implemented.

Partial

iOS

App scaffold and Xcode project exist, but SMS and Photos are Android-only native bridges. Calendar, Gmail, and GitHub use plain OAuth and should work the same way, though iOS hasn't had the same testing attention as Android.

Ready

Desktop / self-hosted

The original mode — run the server yourself and connect it to Claude Code, Cursor, or any MCP client. Gmail and GitHub only, no phone-specific sources.

Try it

There's no app store listing yet. Two ways to get it running:

Nightly APK

A debug-signed build published automatically every day on GitHub Releases. It's meant for testing, not for handing to someone non-technical — you'll need to allow installs from unknown sources, and it isn't signed for the Play Store.

Download nightly build

Build from source

cd PersonalDataHub && pnpm install
cd mobile && npm install && npm run build:android
