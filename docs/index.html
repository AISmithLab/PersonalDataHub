An AI assistant that lives on your phone, not in someone else's cloud.

PersonalDataHub is an open-source app you run yourself. It's a chat assistant that can read your SMS, photos, calendar, email, and GitHub — but only the sources you connect, only the data you allow. Sending an email is staged for your approval; the only thing that acts on its own is an opt-in SMS auto-reply, which you turn on knowingly.

What it actually is

The app is a React Native shell around an embedded server. The server — the same backend used by the self-hosted desktop version — runs inside the phone in a background Node.js thread and talks to the on-screen chat UI over 127.0.0.1.

There's no PersonalDataHub account, no server you sign up for, and no telemetry sent back to us. It's a tool you run, not a service you join. Data still leaves the phone in two cases you control: each connected service's own API (e.g. Gmail's, when you ask about email), and the AI model itself — you bring your own API key for OpenAI, Anthropic, Gemini, or Groq, and whatever the assistant reads to answer your question is sent to that provider as part of the request.

Automations (Skills)

You can define standing rules that fire when something happens — a text arrives, a photo is saved, an email comes in, a calendar event is about to start. Each rule is scoped to specific sources, so a "label incoming receipts" rule can't also read your calendar. Create them by hand in the app's Skills tab, or just ask the assistant to set one up for you in chat.

How access is actually controlled

  • Zero access by default. Connecting a source does not automatically expose it — you set filters on top (date ranges, senders, keywords, hidden fields) before the assistant can query it.
  • Email goes through a staging queue. Drafting, replying, or sending a Gmail message sits in a staging queue until you approve it — there's no code path for the assistant to send email directly.
  • SMS auto-reply is the exception, by design. It's an opt-in toggle: when on, replies are sent immediately with no per-message approval, because the point is to answer texts while you're away from the phone. You approve the feature once, not each message. Turn it off and the assistant can only read, not send.
  • No deletion. There's no delete endpoint for any connected source. The assistant can read and propose, nothing more.
  • Everything is logged. Every read and every proposed action is written to a local audit log with a timestamp and a purpose string, so you can see exactly what was accessed and why.
  • Tokens are encrypted at rest (AES-256-GCM), and on the desktop version the server only binds to 127.0.0.1.

None of this stops you, once you approve something, or stops a connected service's own quota/rate limits. It's a boundary on the assistant, enforced before data or actions reach it — see the full threat model for what it doesn't cover.

Current status

This is an early-stage, actively-developed open-source project — not a polished product. Here's where things actually stand:

  • Android: builds via nightly CI. SMS, Photos, Calendar, Gmail, and GitHub are all implemented.
  • iOS: the app scaffold and Xcode project exist, but the native SMS and Photos bridges are Android-only — those two sources aren't available on iOS. Calendar, Gmail, and GitHub use plain OAuth with no native bridge, so they should work the same way, though iOS hasn't gotten the same testing attention as Android yet.
  • Desktop / self-hosted: the original mode — run the server yourself and connect it to Claude Code, Cursor, or any MCP client. Gmail and GitHub only, no phone-specific sources.

Try it

There's no app store listing yet. Two ways to get it running:

Nightly APK. A debug-signed build is published automatically every day on GitHub Releases. It's meant for testing, not for handing to someone non-technical — you'll need to allow installs from unknown sources on Android, and it isn't signed for the Play Store.

Build from source: 

git clone https://github.com/AISmithLab/PersonalDataHub.git
cd PersonalDataHub && pnpm install
cd mobile && npm install && npm run build:android

Full steps, prerequisites, and troubleshooting are in the Android Build Guide. For the desktop/MCP version, see the Setup Guide.
